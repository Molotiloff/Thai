# Проверка SQL-проекта E1

```sh
.venv/bin/python -m pytest tests/design -q
.venv/bin/ruff check tests/design
```

Это проверки `architecture/thai/schema_draft.sql`, отдельно от старых миграций
и `tests/db` fixtures. Требуются локальные PostgreSQL, createdb/dropdb и asyncpg.
Учётные данные берутся только из THAI_TEST_DATABASE_URL (окружение или `.env.thai`), но имя целевой БД
всегда заменяется уникальным `crm_thai_design_<случайный суффикс>`.
Исходная база не открывается и не изменяется; remote DSN не используется.
Новая БД удаляется в finally, изменения каждого теста откатываются.

Проверяются фактически реализованные локальные ограничения прототипа:
числовые domains, нормализация курса, FK, idempotency key, отложенная балансировка,
неизменность журнала, сторно, клиентский знак и классификация займов,
соответствие договора при FIFO/начислении, расход/выписка, формула закрытия прибыли
и перенос существующего обязательства BestChange без кассового движения.

Это не проверки готовых use cases и не подтверждение всех межстрочных правил:
остатки/порядок FIFO, суммы долей, интервалы условий, period locks, права и
согласованность всех документов с журналом должны проверяться в E2–E8.
