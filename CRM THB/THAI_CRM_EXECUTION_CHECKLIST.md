## Порядок работ и обновления статусов

Основная последовательность: **E1 → E2 → E3 → E4 → E5 → E6 → E7 → E8 → E9 → E10**.
Для E5 сквозная проверка пополнения/возврата зависит от кошельков E6; разработку
представления займов начать по контракту, проверку и `E5.DONE` завершить после E6.
Первым бизнес-разделом после финансовой основы идёт оборотка со ставкой инвестору.
Часть UI можно делать по готовности API, не ожидая окончания всех контекстов.
Отсутствие копии frontend не блокирует backend.

Открытые правила E1.21–E1.28 блокируют только операции, для которых ответ влияет
на деньги. Не считать их согласованными по истечении времени; решения записывать
в архитектурный план и связанные критерии проверки.

Для каждого завершённого этапа заполнять запись:

```text
Этап / задача:
Дата завершения:
Изменённые файлы или commit/PR:
Проверки и результат:
Оставшиеся ограничения:
```

Общий чекбокс этапа отмечается после обязательных задач и его `DONE`.
Не выполненную проверку не отмечать выполненной даже при наличии реализации.
Изменения согласованных правил сначала отражать в архитектуре и списке задач,
затем в коде; закрытые финансовые периоды не пересчитывать незаметно.
