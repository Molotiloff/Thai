# Правила проведения и контрольные примеры

Спецификация E1, 8 октября 2026. Дт/Кт ниже — стороны журнала фирмы.
Каждая строка хранит исходную сумму и оценку USDT; балансируется сумма USDT.
Кошелёк клиента имеет нормальную сторону Кт: положительный остаток означает,
что фирма должна клиенту. Отрицательный остаток означает обратный долг.
Управленческие долги между физическими плательщиками хранятся отдельно от
книги фирмы, но используют тот же идентификатор финансовой операции.

## 1. План счетов

| Purpose | Класс / нормальная сторона | Валюта и аналитика |
|---|---|---|
| cash | asset / debit | Один счёт на инструмент общей кассы |
| client_wallet | liability / credit | Клиент × инструмент; отрицательный остаток допустим по политике |
| best_change_buffer | liability / credit | USDT, экономический получатель Данияр |
| owner_capital | equity / credit | Договор собственника × исходная валюта вклада |
| investor_principal | liability / credit | Договор стороннего инвестора × исходная валюта |
| investor_interest_payable | liability / credit | Договор, USDT |
| owner_profit_payable | liability / credit | SkyEX/ПЕ, USDT |
| expense_receivable | asset / debit | Должник фирмы × валюта расхода |
| personal_expense_funding | equity / credit | Личные расходы собственника на бизнес; не оборотка |
| personal_expense_payable | liability / credit | Личный расход несобственника на бизнес |
| trading_income / trading_loss | income / credit; expense / debit | USDT, сделка |
| transfer_fee_income | income / credit | USDT, перевод |
| operating_expense | expense / debit | Категория, USDT |
| platform_commission_expense | expense / debit | Комиссия BestChange, USDT |
| platform_commission_payable | liability / credit | Платформа, валюта расчёта |
| investor_interest_expense | expense / debit | Договор, USDT |
| fx_income / fx_loss | income / credit; expense / debit | USDT, разница оценки при исполнении |
| period_result / retained_result | equity / credit | USDT, закрытие прибыли |

Счета оборотки различаются по экономической роли вкладчика. Роль owner
и роль investor не взаимоисключающие: конкретный договор выбирает назначение
principal-счёта при создании, использованный договор не переклассифицируется.
Эту привязку задают capital_agreements.principal_kind и capital_principal_accounts:
один счёт на договор и экономическую валюту. Проверка класса счёта — E2–E4.
Базовые корректирующие строки имеют native_amount=amount_usdt и валюту USDT.
Для чистой корректировки carrying value валютного счёта native_amount=0 допустим.

## 2. Матрица операций

| Команда | Дт | Кт | Касса / обязательства |
|---|---|---|---|
| Вклад капитала | cash по оценке вклада | principal по той же оценке | Касса+, FIFO-партия+, доход 0 |
| Возврат капитала | principal по FIFO | cash по WAC | Касса−, партия−; разница FIFO/WAC в fx |
| Начисление процента | investor_interest_expense | investor_interest_payable | Касса 0, долг+ |
| Выплата процента | investor_interest_payable | cash по WAC | Касса−, долг−; оценочная разница в fx |
| Пополнение клиента/партнёра | cash | client_wallet | Касса+, обязательство+, доход 0 |
| Вывод клиента/партнёра | client_wallet по carrying value | cash по WAC | Касса−, обязательство−; разница в fx |
| Перевод между клиентами | wallet отправителя | wallet получателя | Касса 0; оценка и количество переносимые |
| Перевод THB нал→безнал фирмы | cash THB_BANK | cash THB_CASH | WAC переноса сохраняется; общий THB не изменяется |
| Комиссия перевода клиента | client_wallet | transfer_fee_income | Дополнительное списание кошелька, отдельное признание дохода |
| Обмен наличных валют | cash полученного инструмента | cash выданного по WAC | Разница стоимости в trading_income/loss |
| Конверсия только кошельков | wallet отдаваемого клиентом | wallet получаемого клиентом | Касса 0; разница стоимости обязательств в trading_income/loss |
| Расход из кассы | operating_expense доля бизнеса + expense_receivable личные доли | cash | Разница оценки cash/расхода в fx |
| Личный расход собственника | operating_expense доля бизнеса | personal_expense_funding | Касса 0; долги других участников плательщику — в expense_obligations |
| Личный расход Данияра | operating_expense доля бизнеса | personal_expense_payable | Касса 0; не признавать вклад собственника |
| Прямая выплата между участниками | memorandum, без строк GL | — | Только погашение expense_obligations |
| Погашение должником кассе | cash | expense_receivable по исторической оценке | Нет второго расхода/дохода, разница оценки в fx |
| Явное погашение кошельком кассе | client_wallet | expense_receivable | Только отдельная команда после выбора способа расчёта |
| Взаимозачёт личных долгов | memorandum | — | Парные allocations одной валюты, касса 0 |
| BestChange: доля Данияра | trading_income, перераспределение результата | best_change_buffer | Не кассовое поступление; собственникам достаётся только доля бизнеса |
| BestChange: комиссия платформы | platform_commission_expense | platform_commission_payable или cash | Удержание из результата один раз; исполнение определяется ногами сделки |
| Перенос BestChange при закрытии | best_change_buffer | wallet клиента «Баланс Данияр» | Касса 0, прибыль 0, новый доход 0 |
| Закрытие результата | income → period_result; period_result → expense | Соответствующие счета результата | Обнуление P&L периода, без кассового движения |
| Начисление долей собственников | period_result/retained_result | owner_profit_payable | Только распределяемая чистая прибыль |
| Выплата собственнику | owner_profit_payable | cash по WAC | Касса−, долг−; разница оценки в fx |
| Закрытие выписки расходов | memorandum | — | Неизменяемый снимок задолженностей, без повторных долгов |
| Сторно | Стороны всех строк оригинала меняются местами | — | Новая операция, обратные движения/allocations |

В строках с несколькими валютами используются их собственные счёт и native_amount.
Разница оценки добавляется отдельной строкой USDT, не исправлением исходного курса.
Внесение денег собственником на кошелёк группы «Партнер» — клиентское обязательство,
а вклад по договору оборотки — principal. Выбор контекста обязателен до проведения.
Личный расход с нулевой долей бизнеса использует memorandum, поскольку GL не меняется.

Реальный обмен и расчёт BestChange связываются одной операцией: итоговую прибыль
не начислять повторно после уже проведённого обмена. При выплате комиссии платформе
погашается её отдельное обязательство; если комиссия сразу удержана в денежной
ноге сделки, отдельной будущей выплаты нет. Fee/payable подтверждаются legs сделки.

## 3. Себестоимость и контрольные примеры

### Капитал и FIFO

Вклад 1: 35 000 THB, ручной обратный курс 35 THB/USDT → principal 1 000 USDT.
Вклад 2: 18 000 THB, курс 36 → principal 500 USDT. Оборотка 1 500 USDT,
касса 53 000 THB с WAC1 500 / 53 000. Пополнения не входят в прибыль.

Возврат 40 000 THB: партия 1 полностью 35 000/1 000 USDT, партия 2 частично
5 000/138,88888889 USDT. Principal уменьшается на 1 138,88888889,
остаток 13 000 THB /361,11111111 USDT. Выдача в другой экономической валюте
в v 1 запрещена. THB_CASH/THB_BANK остаются разными кассовыми счетами.

Cash списывается по WAC на 1 132,07547170 USDT. Разница 6,81341719 USDT —
fx_income: Дт principal 1 138,88888889; Кт cash 1 132,07547170; Кт fx 6,81341719.
Доход не возникает от нового вклада; здесь он возникает от исторической
оценки возвращаемого обязательства. Последняя выдача позиции забирает весь
оставшийся carrying cost, последняя выдача партии — весь её principal.

WAC на оценённом поступлении=(старый cost+новый cost)/(старое оценённое quantity+новое оценённое quantity).
Количество 0 требует cost 0. Не вести параллельный «баланс фирмы» поверх cash и
inventory: inventory — аналитика тех же активов. FIFO относится к договорам,
WAC к конкретному инструменту кассы. Порядок FIFO=(business_date, effective_at, ID операции, ID партии).
Блокировать договор и партии; отклонять объём сверх доступного остатка.

### Клиентские баты без курса — уточнение 14 октября 2026

Внесение THB_CASH/THB_BANK сначала погашает отрицательный кошелёк по его
исторической оценке. Например, −3500 THB / −100 USDT после обмена закрываются
внесением 3500 THB без нового курса; касса получает 3500 THB / 100 USDT.
Частичное погашение использует пропорциональную оценку, последнее — точный остаток.

Внесение сверх минуса или на пустой кошелёк сохраняет количество без курса.
`unvalued_native` в журнале и соответствующие проекции отделяют это количество
от оценённых денег. Нулевая текущая оценка не означает бесплатную валюту:
до оценки WAC делит cost только на оценённое количество. Возврат неоценённых
батов этому клиенту уменьшает неоценённые кассу и обязательство без прибыли.

По решению пользователя деньги доступны общей кассе. Если обмен, расход либо
выплата с известной оценкой использует этот инструмент, в начале той же операции
весь его неоценённый пул получает оценку операции. Кассовый актив и обязательства
клиентам получают одинаковую сумму USDT; количество на каждом счёте неизменно.
Строки `valuation_component` не попадают в клиентскую выписку как движение денег.
Затем обычные правила обмена/WAC рассчитывают результат. При ошибке откатываются
и оценка, и основная операция; сторно восстанавливает их в обратном порядке.
Исторические проведённые операции миграция не переоценивает.

Дата расчёта кассовой заявки — серверное время проведения, бизнес-день Bangkok;
дата создания заявки остаётся в аудите. Повтор проведения сохраняет исходную дату.

### Процент и прибыль

Полный месяц: база 10 000 USDT, ставка 2% → расчёт 200 USDT.
Менеджер может изменить начисление с причиной; при изменении вклада внутри
месяца окончательное начисление требует его решения, автоматической дневной
формулы нет. Историческая ставка и база остаются в документе.
Выплата 150 USDT погашает 150, остаток 50: сама выплата больше не уменьшает прибыль.
При недостатке прибыли начисление и выплату отдельно утверждает менеджер.

Доход 1 000, расходы бизнеса 300, утверждённый процент 200 → чистая прибыль 500.
Доли 50/50 → SkyEX250, ПЕ 250. Капитал, заём и перенос BestChange не входят
в формулу дохода. Личные доли расходов не вычитаются из прибыли фирмы повторно.

### Заём через кошелёк

Клиент группы partner внёс 7 000 THB по 35: cash+7 000/200 USDT,
wallet+7 000/200 USDT. В займах отображается 7 000 THB, без второй записи долга.
Вывод 2 000 → wallet 5 000. Перевод клиента в balance убирает его из списка
займов, кошелёк и журнал остаются прежними. Отрицательный wallet показывается
с обратным направлением задолженности; значения не брать по модулю.
Нули исключаются API по умолчанию, include_zero=true возвращает их для аудита.

### Обмен и перевод

Выдаём 100 USDT себестоимостью 100, получаем 3 600 THB по 35 → стоимость
102,85714286. Дт cashTHB102,85714286; Кт cashUSDT100;
Кт trading_income 2,85714286. Если клиент только конвертирует остатки кошелька,
те же рыночные оценки применяются к обязательствам; физическая касса не меняется.

Перевод 3 500 THB из наличной кассы в безналичную переносит 100 USDT cost.
Если клиентская комиссия 35 THB, её оценка 1 USDT признаётся один раз отдельно
от 3 500 THB основного перевода. Внешняя банковская комиссия — отдельный расход,
а не автоматический доход фирмы. Сценарий снятия всего кошелька использует
его полный carrying value, без оставшейся «копейки» в USDT.

### Расход и расчёты

Расход 1 000 THB, Данияр 20%, common 80%; common разворачивается
в ПЕ 40%, SkyEX40%. Введённые проценты должны дать 100, рассчитанные суммы
должны дать 1 000 и полную исходную оценку USDT.

Платит ПЕ: Данияр→ПЕ 200 THB, SkyEX→ПЕ 400 THB. Собственная доля ПЕ 400
не создаёт долг самому себе. Расход бизнеса 800/35=22,85714286 USDT;
Кт personal_expense_funding такая же сумма. Касса и кошелёк Данияра не меняются.
Прямое погашение Данияром 50 → его долг ПЕ 150; GL и прибыль не меняются.

Платит касса с carrying rate 1/35: Дт operating_expense 800/35;
Дт expense_receivable 200/35; Кт cash 1 000/35. Данияр→business 200 THB,
долгов SkyEX/ПЕ общей кассе по их бизнес-доле нет. После погашения 200 THB
receivable 0, касса+200, повторного признания 800 THB расхода нет.
Если кто-либо внёс деньги в кассу, а затем фирма заплатила расход, это две
отдельные команды; не помечать такой расход «лично оплатил» второй раз.

Взаимные долги: SkyEX→ПЕ 400 и ПЕ→SkyEX100 THB. Взаимозачёт 100
погашает обе стороны; остаётся 300. EUR/USD/USDT долги с THB не смешиваются.
Снимок месяца: opening 150+accrued 400−settled 50−netted 100=closing 400 THB.
Закрытие фиксирует снимок; перенос opening следующего месяца не создаёт новый долг.

### BestChange в THB

100 USDT, рыночный курс 35, клиентский 36 THB/USDT: положительный спред 100 THB.
Оценка по 35: gross 2,85714286 USDT. По существующему алгоритму fee 30%:
0,85714286 USDT; pool 2; Данияр 1, бизнес 1. Операция обмена признаёт gross,
распределение уменьшает результат на fee и долю Данияра: остаток бизнеса 1.
Комиссия платформы отражается обязательством или уже исполненной денежной ногой.
Прибыль сделок обменника для отчёта уже включает вычет комиссии платформы и доли
Данияра. Из неё далее вычитаются операционные расходы и проценты инвесторам.
При сборке этого отчёта из GL комиссия платформы не попадает второй раз в расходы
бизнеса: income и platform_commission_expense сворачиваются в результат сделки.
Для обратного направления знак/формула берутся из версии существующего калькулятора;
при отрицательном спреде комиссия не выдумывается, отрицательные доли требуют E1.27.

Доля Данияра 1 USDT появляется в profit_buffer чата BestChange. При закрытии
Дт buffer 1; Кт wallet«Баланс Данияр»1. Суммарный долг фирмы Данияру прежний,
cash 0, повторная прибыль 0. Закрытие сохраняет allocations сделок; следующий
запуск не переносит их заново. Поправка требует новой ревизии со ссылками на сторно.

## 4. Проведение и проверка границ

Одна UoW включает документ, строки, оценки, FIFO/долги, проекции и outbox.
Idempotency key возвращает прежний результат только при совпадении command_hash;
изменённая команда с тем же ключом — конфликт. День учёта определяется явно
из бизнес-часового пояса, не из локального времени браузера.

Каждый калькулятор возвращает PostingPlan. Общий сервис проверяет ровный итог USDT,
права, закрытие периода и остатки под блокировками, затем проводит. Ошибка до commit
не оставляет ни денег, ни сообщений. Telegram доставляется из outbox после commit.
Draft допускает незаконченный план; posted — только сбалансированный и неизменяемый.
Сторно воспроизводит точную историческую оценку, а не текущий курс.

Производные документы при сторно учитывают только проведённые оригиналы/компенсаторы.
Для FIFO и процентов запросы остатка должны исключать отменённые allocations,
а journal включает обе стороны компенсации. Ограничения закрытого периода и
зависимостей проверяются прежде записи сторно; произвольное удаление запрещено.
