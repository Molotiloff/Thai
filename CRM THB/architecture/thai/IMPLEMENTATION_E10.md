## Изменения

  при запрещённых Google, старом config, handlers, bot_app и app.container;
  прикладные сервисы не зависят от транспорта и persistence.

- `app/thai_maintenance.py`: утилита backup/restore с отдельной конфигурацией,

  Restore одной транзакцией; проведённые документы не удаляются.
- `deploy/thai/`: инструкция установки, миграций, обновления, аварийного
  восстановления и отката приложения; отдельные systemd units и Nginx template.
  Шаблоны не установлены на сервер; проверка Nginx/TLS/systemd относится к запуску.
- `.env.thai.example`: адрес frontend для локального CORS исправлен на 3001.
  Рабочий `.env` РФ не менялся.

## Контрольный сценарий

На пустой Thai-схеме: инвестор 2%, вклад 1000 USDT и два THB-лота
35000 по 35 и 18000 по 36; отдельный вклад собственника 2000 USDT;
заём клиента группы «Партнер» 100 USDT. BestChange в кошельках клиента:
3500 USDT по рынку 35 / клиентскому 36, клиентский THB-баланс отрицательный.
Доход бизнеса 35 USDT; доля Данияра до закрытия находится в буфере.

Расход 1000 THB оплачивает PE: Данияр 20%, общая касса 80%.
По выписке Данияр должен PE 200 THB, SkyEX должен PE 400 THB;
бизнес-расход 22.85714286 USDT. Кошелёк Данияра автоматически не списывается.
Менеджер подтверждает инвестору 10 USDT. Итог прибыли 2.14285714 USDT,
собственникам по 1.07142857; при закрытии Данияру переносится 35 USDT.

Выплата каждому собственнику 1.071428 USDT, инвестору 10 USDT;
взаимные долги гасятся отдельно по выписке. У собственников остаётся суммарно
0.00000114 USDT невыплаченного обязательства: журнал 8 знаков, валюта выплаты 6.
Остаток не округляется в доход и не теряется. Выплаты не создают второй расход.

FIFO-возврат 40000 THB в следующем месяце закрывает первый лот и часть второго.
Остаток капитала инвестора 1361.11111111 USDT, в THB-лотах 0 и 13000 бат.
Сторно возвращает точную кассовую себестоимость. Выплаты, возврат, погашения
и сторно не меняют октябрьский отчёт или сохранённую месячную выписку.

Затем проекции счетов и кассы в тестовой БД намеренно обнуляются и пересобираются
из журнала: все остатки и стоимости совпадают. pg_dump восстанавливается в новую
БД; сравниваются все public-таблицы, отчёт и снимок закрытия. Проверены запреты
повторного restore в непустую базу, restore в источник, перезаписи backup и
повреждённой контрольной суммы. Все временные БД удаляются fixtures в finally.

В существующий `app.thai_maintenance` добавлена команда `check`: конфигурации,
актуальная ревизия/identity, администратор, рабочие привязки, адрес USDT,
проекции счетов/кассы, баланс журнала и outbox проверяются без записи в БД.
Проверка финансовых данных выполняется в read-only repeatable-read snapshot,
соединение также имеет default_transaction_read_only. Формулы прибыли и FIFO
не копировались: контрольный сценарий продолжает использовать общие сервисы.
JSON содержит только результаты, не выводит DSN, секреты, имена и суммы клиентов.
`--output` сохраняет отчёт 0600, `--expect-empty` проверяет новый старт без удаления
данных, `--frontend-url` добавляет локальный HTTP smoke без прокси и без перехода
в Telegram. Никаких сообщений ботом и автоматического запуска процессов нет.

`db_asyncpg.schema_identity` владеет общей проверкой подключения и признаками
актуальной Thai-схемы. Config/runtime, migrator, maintenance и временные тестовые
БД используют эту проверку до соединения: 5432/неуказанный порт и переопределение
host/port в query запрещены. Bootstrap Thai читает только явно выбранный config,
не наследует российскую `.env` и не требует JWT/bot token для миграций.
Подстановка переменных из внешнего окружения в `.env.thai` выключена.

API `/health/live` возвращает состояние HTTP-процесса; `/health/ready` проверяет
доступность актуальной изолированной схемы и возвращает 503 при проблеме,
не раскрывая реквизиты. Runtime отказывается запускать администраторов/workers
со старой схемой. Начало API lifespan проверяет тот же контракт.

Проверки: **858 passed** полного unit/Thai/design набора; затем **7 passed**
финальных readiness/HTTP smoke проверок. Ruff успешен, циклов среди **474**
модулей нет. В частности проверены:

- отказ от неверного DSN до подключения/migration/createdb;
- отсутствие наследования российского DATABASE_URL и dotenv expansion;
- неизменность всех таблиц при read-only инспекции, безопасные ошибки;
- расхождение доменов, отсутствие настроек и непустой релизный старт;
- обнаружение drift проекций и failed/stale outbox;

- контрольный месяц, FIFO, выплаты и pg_dump/restore всех public-таблиц.
