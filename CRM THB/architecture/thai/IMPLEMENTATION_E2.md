# Этап 2: отдельная Thai-база и миграции

8 октября 2026. Локально создан **отдельный PostgreSQL на 127.0.0.1:5433**,
база `thai_crm`, владелец `thai_crm`. Сервер и текущая база на 5432 не менялись.
Исходный `.env` сохранён. Подключение новой CRM находится в локальном `.env.thai`.

## Созданные объекты

Независимая цепочка `db_asyncpg/thai_migrations`:

| Ревизия | Результат |
|---|---|
| thai_0001 | Идентификатор базы, валюты/инструменты, участники, кошельки, журнал, себестоимость, капитал/FIFO, проценты, расходы, прибыль и BestChange |
| thai_0002 | Защита проведённых документов и курсов; интервалы ставок/долей, реквизиты погашения расходов, запрет отрицательной кассы |
| thai_0003 | Справочник прав, Telegram-связи, заявки, payment-watch и независимый архив сообщений |
| thai_0004 | Новые справочники, общая касса, SkyEX/ПЕ/Данияр, договоры собственников с 0% и условия прибыли 50/50 |
| thai_0005 | Защита классификации использованных счетов и привязок кассы/кошельков |

По одному кассовому счёту на каждый из восьми инструментов. Безналичная касса
одна — THB_BANK. Экономические валюты THB/USDT/USD/EUR/RUB имеют отдельные формы денег.
Партнёрские займы читаются из клиентского журнала, дополнительного баланса займов нет.

Seed не содержит клиентов, финансовых операций, курсов, вложенных денег,
Telegram ID или доступов реальных пользователей. Нулевые проекции кассы — исходное
пустое состояние. Единственный системный пользователь неактивен и не имеет прав;
он служит автором начальных условий. Договоры SkyEX/ПЕ пустые, ставка 0%.

`role_permissions` задаёт согласованную матрицу. Проверка прав в командах появится
в E3–E8; запись роли в справочник сама по себе не запускает финансовую операцию.

## Запуск миграций

Для уже созданного локального экземпляра:

```sh
.venv/bin/dotenv -f .env.thai run -- .venv/bin/python -m db_asyncpg.bootstrap --schema thai
.venv/bin/dotenv -f .env.thai run -- .venv/bin/python -m db_asyncpg.bootstrap --schema thai --status
```

Повторная команда не создаёт справочники заново. Это штатный bootstrap только БД:
ему не нужны токен бота и Telegram-чаты. `alembic.ini` выбирает Thai по умолчанию.
Обновление 14.10.2026: российская цепочка, `alembic-legacy.ini` и режим
`--schema legacy` удалены. Допустима только Thai-схема; чужая БД отклоняется.
Флаг --status только читает имя БД, порт, семейство и установленную ревизию;
проверенный локальный результат: thai_crm / 5433 / thai / thai_0005.

Migrator проверяет тип целевой БД до DDL, использует отдельную таблицу
`alembic_version_thai` и сериализует миграции транзакционной advisory-блокировкой.
Чужая или неизвестная непустая БД вызывает ошибку без создания Thai-объектов.
Первая SQL-миграция дополнительно требует пустую схему public.

Читаемый снимок — `db_asyncpg/schema.sql`, собирается из файлов новой цепочки.
Российский снимок и старые ревизии удалены из проекта 14.10.2026.
Тайские ревизии и их SQL сохранены без изменений. Снимок служит для просмотра,
установка выполняется через единственный Thai Alembic environment.

На другом компьютере с установленным PostgreSQL для такого же локального
экземпляра можно выполнить:

```sh
.venv/bin/python -m db_asyncpg.local_thai
```

Команда создаёт только новый экземпляр на 5433. Занятый порт, существующий каталог
или `.env.thai` — ошибка; существующие данные не перезаписываются.
Каталог `.runtime/thai-postgres` и `.env.thai` исключены из Git.
Пароли сгенерированы, локальные файлы с ними имеют права 0600.
Роль приложения не superuser; отдельная роль thai_test создаёт временные базы тестов.

Для управления уже созданным локальным сервером из корня проекта:

```sh
pg_ctl -D "$PWD/.runtime/thai-postgres" status
pg_ctl -D "$PWD/.runtime/thai-postgres" -l "$PWD/.runtime/thai-postgres.log" start
pg_ctl -D "$PWD/.runtime/thai-postgres" stop -m fast
```

В конфигурации нового экземпляра закреплены 127.0.0.1, порт 5433, Asia/Bangkok
и отдельный socket directory. Автозапуск при
перезагрузке компьютера пока не настраивался. Это локальное окружение разработки.

## Согласованные правила и расширения схемы

- Все клиентские кошельки могут быть отрицательными, без отдельного разрешения.
  Остаток физической кассы и её себестоимость отрицательными быть не могут.
- Убыток сохраняется в отчёте своего месяца; автоматического переноса убытка на
  будущую распределяемую прибыль нет. Отрицательных выплат собственникам нет.
- Погашение расхода отдельно от начисления. Возможны прямой платёж, касса или
  явная команда списания кошелька. Автоматического удержания Данияра нет.
- `expense_resolutions.currency_code/amount` — исходная валюта и сумма долга;
  `payment_instrument_code/payment_quantity` — чем фактически погасили.
  `payment_rate_snapshot_id` хранит курс погашения: для долга THB из USDT это
  снимок THB с ручным курсом THB за 1 USDT, не курс USDT=1. Суммы обязательств
  остаются в THB; исходную оценку расхода не переписывать. Проверка соответствия
  валют, владельца кошелька, округлений и остатка долга — E7.
- Возврат THB допускается cash/bank; другие формы возвращаются исходным видом.
  Principal списывается по FIFO, касса по WAC, разница — валютный результат USDT.
- Бизнес-даты — Asia/Bangkok. Менеджер проводит операции и закрывает месяц;
  владелец/администратор меняет права/условия и исправляет закрытый месяц новой
  ревизией с причиной. Проведённые документы не редактируются.

## Проверка и граница готовности

```sh
.venv/bin/python -m pytest tests/unit tests/thai tests/design -q
.venv/bin/ruff check .
```

Проверено: 522 теста прошли, включая 16 проверок реальной цепочки Thai и 28
проверок проекта E1. Новые PostgreSQL fixtures используют только отдельный
THAI_TEST_DATABASE_URL из окружения или `.env.thai`, не текущий DATABASE_URL.
Временные базы удаляются после проверки. Legacy-совместимость также проверена
во временной базе на 5433; реальная российская база не использовалась.

Этап 2 создаёт схему и справочники. UoW, финансовые use cases, UI и новые adapters
реализуются далее. Запуск старых repositories на Thai намеренно блокируется
до подключения этих adapters. Межстрочные проверки сумм/FIFO/погашений, блокировки
периода, точное сторно и восстановление проекций относятся к E3–E8: готовая схема
не означает, что приложение уже может проводить реальные сделки.
