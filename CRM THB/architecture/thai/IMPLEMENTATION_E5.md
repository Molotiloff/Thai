# Этап 5: займы из клиентских кошельков

8 октября 2026. Раздел займов реализован как чтение обычных кошельков клиентов
группы с постоянным кодом **`partner`**. Суммы сохраняют знак и исходный инструмент.
Отдельного займа, второго баланса или начисления поверх кошелька нет.

Миграция `thai_0008` применена только к `thai_crm` на **127.0.0.1:5433**;
имя, порт и ревизия проверены командой bootstrap --status.
Российская БД на 5432 и исходный `.env` не изменялись.
Реальные клиенты и деньги не создавались; одноразовые тестовые базы удалены.

## Компоненты

| Компонент | Ответственность |
|---|---|
| `services/clients/directory.py` | Клиенты, справочник групп, назначение группы, идемпотентный аудит CRM |
| `services/clients/ports.py` | Контракты клиентского UoW, справочника и чтения кошельков/займов |
| `services/clients/wallets.py` | Общие команды внесения/возврата через кассу для всех групп |
| `services/loans.py` | Направление долга, раскрытие до истории и пагинация раздела займов |
| `db_asyncpg/thai_clients/` | PostgreSQL-реализация контрактов, чтение из проведённого журнала |
| `domain/wallet_valuation.py` | Историческая оценка погашаемого знакового обязательства |
| `domain/finance/fx_result.py` | Общий расчёт валютного результата для капитала и кошельков |
| `api/thai_clients.py` | API групп, клиентов, кошельков и займов |

Клиентский UoW расширяет финансовый, используя одну connection. Общая точность
Decimal установлена в базовом UoW; капитал и кошельки не дублируют эту настройку.
Сервисы зависят от портов, правила оценки не зависят от asyncpg/FastAPI/Telegram.
Общий сервис проведения обеспечивает блокировки, атомарность, снимки курсов,
себестоимость кассы, повтор команды и outbox.

## Классификация и аудит

`client_groups.code` — стабильный первичный ключ, `name` — изменяемое отображение.
В займы входит только `partner`, независимо от названия. Группа `balance` и
пользовательская группа с названием «Партнер» туда не входят.
Коды и признак классификации защищены от изменения в БД.

Роль собственника, договор капитала и группа клиента независимы. Собственник
может иметь обычный клиентский кошелёк в группе «Баланс»; его капитал не появляется
в займах. Назначение «Партнер» — отдельная команда, не автоматическое следствие роли.
Технический `profit_buffer` не включается в займы.

Создание клиента без Telegram-чата создаёт восемь пустых клиентских счетов.
Это минимальная общая основа для проверки займов; привязки Telegram, сделки,
комиссии перевода и оставшиеся клиентские сценарии относятся к E6.
Можно зарегистрировать нового участника или клиента для существующего участника.

Изменение группы записывается в `client_directory_events`: автор, время, причина,
старое/новое значение и ключ команды. Аудит неизменяемый. Повтор одинаковой
команды возвращает прежний ответ, изменённая команда с тем же ключом — конфликт.
Смена группы не создаёт проводок, финансовых операций или финансового outbox;
выписка и остатки кошелька сохраняются. Изменять каталог может менеджер и выше,
чтение использует финансовые права пользователя.

## Балансы и итоги

Займы и кошельки читают `posted_account_balances`, то есть сумму проведённых строк
журнала. Повреждённый кеш проекции не меняет показанный заём.

- Положительный остаток: `exchange_owes_client` — обменник должен клиенту.
- Отрицательный: `client_owes_exchange` — клиент должен обменнику.
- Нулевой: `settled`; по умолчанию нули скрыты, `include_zero=true` раскрывает их.

Пагинация списка идёт по клиентам: все их инструменты попадают на одну страницу.
Остатки THB_CASH/THB_BANK отдельные. Итоги дают разбивку по инструментам и по
экономическим валютам, в том числе общий THB. Разные валюты не суммируются в
одну нативную сумму. Помимо знакового net показываются отдельно `exchange_owes`
и `clients_owe`, чтобы противоположные долги не скрывались взаимным вычитанием.
Обе разбивки итогов читаются в одном repeatable-read snapshot.

## Поступление и возврат

Партнёр использует те же `WalletCashService.deposit/withdraw`, что и любой клиент.
Внесение увеличивает кассу и клиентское обязательство; возврат уменьшает оба.
В обычном сценарии нового капитала и дохода не появляется.
Пример: **100 000 THB внесено, 30 000 возвращено → 70 000 THB** в кошельке и займах.

Поступление валюты требует ручной оценки USDT (USDT всегда 1).
Возвращаемое положительное обязательство списывается по исторической carrying
стоимости; касса — по WAC. Разница отражается общим валютным результатом.
Кошелёк может уйти в минус при достаточной кассе; новая задолженность тогда требует
ручного курса. При погашении отрицательного кошелька сначала закрывается его
историческая стоимость, а новый положительный остаток оценивается по новой
котировке. Нулевое количество не оставляет хвоста стоимости.

Выписка даёт знаковое движение, оценку, остаток после операции, автора,
даты, исходную команду и ссылку на сторно. Курсор истории — ID операции.
Восстановление проекций/обычное точное сторно доступны через общий финансовый API.

## API

Runner: `.venv/bin/python -m api.thai_server`, отдельный `.env.thai`, порт 8001.
Версия API 0.5.0; Bearer, Decimal-строки и ошибки общие с E3/E4.

- `GET/POST /api/v1/client-groups`;
- `PUT /api/v1/client-groups/{code}/name`;
- `GET/POST /api/v1/clients`;
- `PUT /api/v1/clients/{id}/group`;
- `GET /api/v1/clients/{id}/wallets`;
- `GET /api/v1/clients/{id}/wallets/{instrument}/history`;
- `POST /api/v1/clients/{id}/wallets/{instrument}/deposits` и `/withdrawals`;
- `GET /api/v1/loans?client_id=…&after_client_id=…&limit=…&include_zero=…`;
- `GET /api/v1/loans/totals?client_id=…`;
- `GET /api/v1/loans/{id}/wallets/{instrument}/history`.

Строка займа содержит `history_url` обычной выписки клиента. После перевода в
«Баланс» эта выписка остаётся доступной; маршрут истории раздела займов отклоняет
клиента вне «Партнер». CORS разрешает PUT для назначения/переименования групп.
Новые страницы bookkeeping и Telegram-вход ещё относятся к следующим этапам.

частичный возврат, совпадение счетов кошелька/займа, отсутствие нового капитала
и прибыли, неизменность выписки при смене группы, одинаковые имена групп,

откат регистрации после ошибки аудита, права и CORS/API.
