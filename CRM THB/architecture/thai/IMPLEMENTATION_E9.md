## Backend

`db_asyncpg/thai_reports.py` предоставляет:

- сессию активного пользователя, роли и разрешения;
- список восьми инструментов и карточку клиента;
- главную в одной read-only транзакции `REPEATABLE READ`: касса, обязательства
  клиентских кошельков, партнёрская часть обязательств, оборотка, проценты,
  текущие долги расходов и результат выбранного месяца;
- журнал с фильтрами месяца, валюты, участника, счёта и курсорной пагинацией.

Результат главной содержит `as_of` и идентификатор PostgreSQL snapshot.
Деньги кассы, капитал и обязательства не складываются между собой. Отрицательные
кошельки выделены как суммы, которые должны клиенты. Займы показывают ту же
партнёрскую часть кошельков; повторного обязательства не создают.
Суммы передаются десятичными строками, расчёт прибыли использует общий domain
`summarize`, который применяется и при закрытии. Отдельной формулы во frontend нет.

Новые GET маршруты, защищённые существующей проверкой JWT и `finance.read`:

| Маршрут | Назначение |
|---|---|
| `/api/v1/session` | Пользователь, роли, разрешения |
| `/api/v1/instruments` | Инструменты |
| `/api/v1/clients/{id}` | Клиент и группа |
| `/api/v1/reports/dashboard?period=YYYY-MM-01` | Главная |
| `/api/v1/reports/operations` | Журнал и фильтры |

В существующие query/API добавлены фильтр клиента для сделок, фильтры месяца,
участника и валюты для расходов, суммы внесения/снятия в договорах капитала,
исторические курсы вкладов, названия счетов/участников и курсы проводок,
статьи результата для источников сохранённого закрытия. Финансовые команды,
проверка прав, FIFO, ревизии и транзакции используют существующие E3–E8 сервисы.

## Вход, ошибки и повтор команд

`THAI_API_BASE_URL` — единственный адрес backend нового интерфейса. Он серверный,
без fallback к старому `.env`, Google, mock или российскому API. JWT проверяется
через Thai `/session`; отдельная cookie `thai_access_token` имеет HttpOnly,
SameSite=Lax и Secure в production. Старый OIDC не используется.
Браузер вызывает same-origin `/api/thai/*`; BFF разрешает только известные
контексты и проверяет Origin относительно browser-facing Host, включая запуск
через localhost/127.0.0.1. Серверные чтения не кэшируются и имеют timeout.

Права скрывают недоступные команды, а окончательную проверку выполняет backend.
Форма проверяет ID и сумму процентов без float. Денежные строки не переводятся
в JavaScript Number. До hydration форма отключена; login имеет настоящий
POST fallback, чтобы токен не попадал в query string.

Ключ идемпотентности и effective_at сохраняются для одинакового содержимого при
сетевом повторе. Во время запроса поля/кнопки заблокированы, после успеха
повторная кнопка отключена. «Новая операция» явно начинает новую команду.
Ошибка API показывается пользователю; ошибка загрузки не подменяется нулевыми
балансами. Отсутствие закрытия отличается от ошибки чтения отчёта.

## Запуск

Backend из его папки:

```sh
.venv/bin/python -m api.thai_server
```

Frontend из папки `bookkeeping thai`:

```dotenv
THAI_API_BASE_URL=http://127.0.0.1:8001/api/v1
```

```sh
pnpm dev
# http://localhost:3001
```

`.env.local` уже содержит отдельный адрес API 8001. Dev и production start
используют порт 3001. Нужны отдельный Thai bot token, роль пользователя и `/token`
для обычного входа; настройка production-домена и окружения относится к E10.
