# Этап 3: финансовый журнал и транзакции

8 октября 2026. Общая основа проведения операций реализована. Миграция
`thai_0006` применена к `thai_crm` на **127.0.0.1:5433**. База на 5432 и
исходный `.env` не изменялись; реальные финансовые операции не создавались.

## Устройство

| Компонент | Ответственность |
|---|---|
| `domain/finance/models.py` | Неизменяемые суммы, курсы, команды, строки журнала, проверка баланса, округление и распределение остатка |
| `services/finance/ports.py` | Узкие контракты журнала, счетов, документов, outbox и UoW |
| `services/finance/posting.py` | Проведение, перевод между кассами одной валюты, сторно и восстановление проекций |
| `db_asyncpg/thai_finance/` | asyncpg-репозитории, транзакция, чтение истории и очередь доставки |
| `app/container.py` | Сборка Thai-сервисов; вход через `ApplicationContainer.build(pool)` |
| `api/thai_finance.py` | Авторизованный финансовый API с суммами в строках |
| `services/finance/outbox.py` | Доставка после commit через отдельный контракт транспорта |

Domain не зависит от asyncpg, FastAPI или Telegram. Сервисы используют порты,
репозитории получают одну connection UoW. Документ, снимки курсов, журнал,
проекции кассы и событие outbox сохраняются одной транзакцией. Предметные сервисы
следующих этапов передают расчёт проводок и writer документа в общий сервис;
отдельные балансы поверх журнала не создаются.

## Денежные правила

- Входные суммы — Decimal или строки. Float, бесконечность, превышение диапазона
  и точности отвергаются. THB имеет два знака; точность инструментов читается из
  справочника (USDT-касса — 6). Оценка USDT и счета без формы денег имеют
  8 знаков; оценка округляется HALF_UP.
- Прямой курс означает USDT за единицу, обратный THB — THB за USDT.
  Оригинальная котировка и нормализованный курс с 18 знаками сохраняются.
- Журнал балансируется в USDT; PostgreSQL дополнительно проверяет баланс,
  точность, соответствие снимка курса и кассовых движений. Memorandum-документ
  сохраняет решение без проводок. Начисление обязательства само по себе кассу
  не меняет; клиентский кошелёк может быть отрицательным.
- Общая касса имеет восемь отдельных счетов. Cash transfer сохраняет стоимость
  перемещаемой валюты; списание использует WAC. При выдаче всего остатка забирается
  вся оставшаяся стоимость, без округлительного хвоста. Касса не уходит в минус.
- Счета блокируются по ID, позиции — по коду инструмента. Новое проведение
  и сторно используют общий барьер; восстановление проекций и изменение
  блокировок месяца получают исключительный барьер. Закрытие периода в E7/E8
  должно брать исключительный барьер **до** создания закрывающей операции.
- Повтор одинаковой команды возвращает существующий результат даже после
  закрытия месяца; изменённая команда с тем же ключом вызывает конфликт.
  Повтор по другому ключу считается другой командой.
- Сторно сохраняет исходные суммы и снимки курсов. Нельзя повторно сторнировать
  операцию, отменять её до зависимых документов/последующих кассовых движений
  или затрагивать закрытый период. Отмена оборотки, расходов, сделок и закрытий
  через общий сервис блокируется: предметный сервис должен отменить также
  распределения и связи. Эти сервисы реализуются в E4–E8.
- Производные балансы и себестоимость восстанавливаются из проведённого журнала.
  Испорченный кеш не используется как исходный баланс новой операции.

## API и доставка

```sh
.venv/bin/python -m api.thai_server
```

Runner требует отдельный `.env.thai`, загружает его с override и не запускает
старый бот. Локально добавлены отдельный JWT-secret и адрес **127.0.0.1:8001**;
секреты не включены в исходники. Миграции автоматически при старте API не выполняются.

Маршруты `/api/v1/finance`:

- `GET /cash`, `GET /operations?before_id=…&limit=…`, `GET /operations/{id}`;
- `POST /cash-transfers`, `POST /operations/{id}/reversal`;
- `POST /projections/rebuild` — владелец/администратор.

Bearer JWT проверяется по отдельному секрету; пользователь и актуальные права
читаются из Thai-базы. Seed не выдаёт доступ реальным пользователям.
Вход через Telegram и создание пользователей относятся к следующей адаптации
CRM; готовность финансового API не означает готовность интерфейса обменника.
Произвольный журнал через API не публикуется.

Суммы в ответах передаются строками. Ошибки имеют оболочку `error.code/message`;
история использует курсор ID, детали показывают автора, даты, команду, причину
сторно, снимки в строках и заметку документа. Бизнес-дата по умолчанию — Bangkok.

Outbox записывается вместе с деньгами, доставка выполняется после commit.
Worker использует SKIP LOCKED, срок аренды и уникальный lease token.
Сбой транспорта оставляет финансовую операцию проведённой; событие повторяется.
Доставка как минимум один раз: транспорт должен учитывать `event_key`, поскольку
сбой после отправки, но до подтверждения может повторить уведомление.
Реальный Telegram-транспорт подключается при адаптации Telegram-сценариев.

## Проверка

```sh
.venv/bin/python -m pytest tests/unit tests/thai tests/design -q
.venv/bin/ruff check .
```

Проверены unit-правила сумм/курсов и работа на одноразовых PostgreSQL-базах
отдельного сервера: rollback на разных стадиях, пять параллельных повторов одной
команды, конкурентные списания, конфликт ключа, закрытый месяц, права,
сторно зависимостей, восстановление проекций, отрицательный клиентский остаток,
документ без проводок, полная выдача большой суммы без потери цифр, неверная
себестоимость, API-аудит, отказ доставки и перехват истёкшей аренды.
Проверки используют только `THAI_TEST_DATABASE_URL`; действующая БД на 5432
не используется. Общий результат: **560 тестов**, Ruff без ошибок.
