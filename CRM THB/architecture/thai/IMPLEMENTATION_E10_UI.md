# E10: оформление и экран сделок

Дата: 09.10.2026. Выполнено дополнение UI перед общей приёмкой E10.

## Согласованный состав операций

Продажа, покупка, внесение, выдача, клиент → клиент, конвертация,
наличный ↔ безналичный бат, BestChange. Доставка и переводы между городами
исключены по ответу пользователя; юань, инвойс и ручная операция прибыли также
не предлагаются в тайской форме.

## Реализация

Frontend: `/Users/molotiloff/VSProjects/crm_skyex/bookkeeping thai`.
Внешний вид использует CSS и компоненты российской CRM: темы, заголовки,
карточки, вкладки формы и канбан. Общие заголовки и панели Thai тоже приведены
к этому оформлению. Российская папка `bookkeeping` не изменялась.

`src/thai/deals` содержит модель отображения, фабрику спецификаций форм,
реестр с канбаном и форму новой сделки. Общий `ActionForm` отвечает за отправку,
блокировку повторов и отображение ошибок. Денежные значения передаются строками;
финансовые расчёты остаются на backend.

GET `/api/v1/deals/workspace` объединяет заявки и движения кошельков в одном
снимке PostgreSQL. Сводка и колонки учитывают все отфильтрованные документы,
а не только текущую страницу реестра. Статусы соответствуют тайской модели:
новая, готовая к проведению, проведённая, отменённая. Поиск поддерживает клиента,
получателя перевода и идентификатор документа; пагинация использует курсор.

POST `/api/v1/clients/transfers` использует `ClientWalletTransferService`:
переводит одну валюту между обычными кошельками, не изменяет кассу,
допускает отрицательный остаток и сохраняет оценку обязательств с отдельным
валютным результатом. Блокировки клиентов и счетов берутся в стабильном порядке.
Проведение, права, ключи идемпотентности, ревизии и сторно используют общую
финансовую инфраструктуру. Новая таблица и миграция не требуются.

POST `/api/v1/best-change/preview` вызывает тот же `calculate_best_change`, что
проведение, без создания сделки или проводок. Авторасчёт отображает сумму THB,
спред, комиссию, долю Данияра и прибыль бизнеса в USDT. Для обычных заявок
историческая себестоимость определяется при проведении; форма её не выдумывает.

## Проверки

- Общий прогон unit / PostgreSQL / API / design до последнего расширения теста:
  670 passed; отдельные проверки переводов и preview после расширения: 4 passed.
- Ruff по всему backend: без ошибок.
- Frontend: TypeScript, ESLint и production build прошли.
- Браузер: вход тестовым владельцем, сводка статусов, канбан и реестр;
  восемь вкладок новой сделки; BestChange 100 USDT по рыночному курсу 35 и
  клиентскому 36 → 3600 THB, спред 2.85714286 USDT, комиссия 0.85714286,
  Данияру 1, бизнесу 1 USDT.
- Через форму выполнен перевод 70000 THB между синтетическими клиентами;
  открыт документ с двумя проводками по 2000 USDT. Касса не затрагивается.
- PostgreSQL-тесты: сохранение кассы и стоимости, отрицательный кошелёк,
  повтор без дубля и конфликт изменённого запроса, сторно, восемь параллельных
  встречных переводов, отсутствие пересечений страниц, API-аутентификация,
  валидация и отсутствие денежных записей при preview.
