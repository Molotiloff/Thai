# Проверка итоговой схемы Thai CRM

Дата: 14.10.2026. Ревизия: **thai_0021**.
Проверка выполнена на временных локальных базах изолированного PostgreSQL
**5433**, версия `14.15 (Homebrew)`. Рабочие данные CRM не изменялись;
подключений к 5432 не выполнялось. Linux-сервер ещё не развёрнут.

## Источники и результат сверки

- [x] В цепочке ровно 21 последовательная Thai-миграция, без веток legacy.
- [x] Миграции с нуля применились и повторный upgrade не дублирует seed.
- [x] [schema.sql](../../db_asyncpg/schema.sql) совпадает с замороженными SQL
  миграций с явным префиксом `SET search_path TO public`.
- [x] Вторая временная база создана из schema.sql. Полные `pg_dump --schema-only`
  обеих баз совпали: таблицы, колонки, типы, функции, представления, индексы,
  ограничения, последовательности и триггеры.
- [x] Из сравнения исключены только таблица установки `alembic_version_thai`
  и случайные служебные restrict-токены pg_dump. Прикладной DDL не нормализовался.
- [x] SQL-проверка нулевого старта выполнена успешно в read-only транзакции.
- [x] Отдельный тест проверяет отказ проверки нулевого старта на уже использованной базе.
- [x] Защита от неизвестной/российской схемы проверяется на временных базах
  с имитацией чужих таблиц. Legacy-режим отвергается до подключения.

При сверке исправлено расхождение `search_path`: ранее снимок наследовал
`"$user", public`, тогда как Alembic устанавливает `public`. Функции с
`SET search_path FROM CURRENT` теперь получают одинаковую настройку.
Замороженные миграции не переписывались, новая ревизия для этого не нужна.

Условия процентов хранятся отдельно от фактов вкладов: у одного вкладчика
может быть история условий без изменения старых начислений. При изменении
вклада и недостатке прибыли итоговое начисление определяет менеджер.
Собственники получают договорённую долю чистой прибыли, не фиксированный процент
инвестора. Возвраты капитала — FIFO в исходной валюте с исторической оценкой.
Капитал не смешивается с кошельками клиентов и займами.

Начальный seed содержит 8 инструментов и 8 кассовых счетов:
THB_CASH, THB_BANK, USDT, USD_WH, USD_BL, EUR, EUR500, RUB.
Нет клиентов, финансовых операций, проводок, вкладов и ненулевых остатков.
Созданы начальные справочники/условия собственников; это не внесённые деньги.
Первый запуск main.py создаст администраторов и настроенных служебных клиентов.

## Повторение проверки

До очистки полная регрессия `tests/unit tests/thai tests/design tests/message_archive`:

Ruff для изменённого теста прошёл. Shell-блоки инструкции проверены через bash -n;
Nginx и systemd на этой macOS не установлены, их проверка включена в серверный план.

```bash
.venv/bin/python -m pytest tests/thai/test_migrations.py tests/design/test_thai_schema.py tests/unit/test_thai_migration_configuration.py -q
.venv/bin/ruff check tests/thai/test_migrations.py
```

Тестовые базы создаются и удаляются через `tests/postgres.py` только на локальном
изолированном сервере из THAI_TEST_DATABASE_URL с явно заданным портом,
отличным от 5432. Для релизной конфигурации использовать 5433. Нужны createdb,
dropdb, pg_dump и отдельный тестовый пользователь с правом создания временных баз.
Рабочему пользователю **thai_crm_app** такое право не требуется.

На целевом сервере повторить установку миграций и
[verify_initial_database.sql](verify_initial_database.sql) по
[плану развёртывания](../PRODUCTION_DEPLOY.md). Версию PostgreSQL сервера,
ограниченную рабочую роль, HBA, TLS и systemd нужно подтвердить там;
локальные проверки не являются проверкой этих настроек сервера.
Снимок schema.sql служит для сверки; устанавливать БД через bootstrap Alembic.

## Совместимость начальной установки с PostgreSQL 16

В thai_0004 исправлено имя локальной PL/pgSQL-переменной автора seed:
`system_user` → `bootstrap_actor_id`. В PostgreSQL 16 SYSTEM_USER является
специальным выражением типа text и конфликтовало с передачей BIGINT created_by.
Исправление в ранней ревизии необходимо для установки с нуля: отдельная новая
миграция не смогла бы выполниться после ошибки в thai_0004. Схема и данные seed
не изменились; уже установленные базы повторно не засеваются. Ревизия thai_0021
сохранена. SQL-снимок пересобран, его актуальный SHA-256 приведён выше.
CI запускает PostgreSQL 16 с PGPORT=5433 и отображением 5433:5433;
порт внутри контейнера также 5433, поэтому проверки inet_server_port не требуют
ослабления. Основание настройки порта: [PostgreSQL postgres](https://www.postgresql.org/docs/16/app-postgres.html).

До исправления сбой thai_0004 воспроизведён на PostgreSQL 16.14.
После исправления на временном PostgreSQL 16.14 с реальным портом 5433 выполнена
та же команда, что в CI: `python -m pytest tests/unit tests/thai tests/design tests/message_archive -q --tb=short`.
Результат: **913 passed**, одно прежнее предупреждение Starlette/httpx.
Включены установка с нуля, повторный upgrade, сверка PostgreSQL DDL со снимком,
проверка нулевого старта и готовности runtime. Ruff и git diff --check прошли.
Временный кластер остановлен и удалён, рабочие базы не изменялись.
GitHub Actions после push нужно проверить отдельно; удалённый CI этим локальным
прогоном не запускался.
