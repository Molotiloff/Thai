# Этап 5. Контракт Thai API и загрузка клиентов

## Контракт

`pnpm run generate:api` из каталога frontend запускает Python-модуль
`api.export_openapi`. Он собирает ту же фабрику `create_api_app`, что и
backend, и экспортирует схему без подключения к PostgreSQL. Единственный
сгенерированный файл находится в `src/api/openapi.ts`. В CI режим `--check`
сверяет его с результатом генерации на Python 3.12 и Pydantic 2.11.10.
Переменная `THAI_API_PYTHON` позволяет выбрать интерпретатор. По умолчанию
используется backend `.venv`.

Контракт содержит 88 путей и 98 операций. Дополнительная операция возвращает
активных клиентов для форм через `GET /api/v1/clients/options`. Старый
генерируемый контракт и его цепочка вызовов заменены после сверки импортов и
манифеста серверных действий Next.js. Рабочие страницы используют `apiGet`,
запись форм по-прежнему проходит через BFF.

Список и карточка расходов читают DTO из сгенерированных типов. Доля расхода,
личная оплата и баланс кошелька проверяются как разные поля. Суммы в JSON
сериализуются прежним способом в строки. Формат 422 в OpenAPI описывает
фактический ответ `error.code`, `error.message` и необязательный `error.fields`.

## Замеры

Локальная копия дампа от 24 ноября 2026 года была открыта только для чтения.
Замерялся размер несжатого JSON штатных ответов API. В снимке было 21 активное
имя, включая 7 клиентов группы «Партнёр».

| Загрузка клиентских данных | Было | Стало |
| --- | ---: | ---: |
| Список для поиска в новой сделке или BestChange | 1 запрос, 3 012 байт | 1 запрос, 843 байта, −72% |
| Расходы при привязанных кошельках SkyEX и ПЕ | 1 запрос, 82 422 байта | 0 запросов, 0 байт |
| Форма привязки кошелька при наличии доступа, сравнение ответов одной базы | 1 запрос, 82 422 байта | 1 запрос, 236 байт |

При больших каталогах список для форм также сокращает последовательные
страницы по 100 записей до одного ответа. Порядок по ID, дубликаты имён и
выбор по ID сохранены. Опции контрагента по-прежнему берутся из
`/deals/counterparties`, где проверяется наличие активного чата.

Отдельно проверен `GET /clients/workspace?client_id=…`. Для выбранного клиента
он вернул ту же карточку, что и полный каталог, в 7 362 байтах вместо
82 422. Страница `/clients/[id]` продолжает загружать каталог для поиска,
показателей и мгновенного переключения боковой панели. Этот интерфейс входит
в самостоятельный сценарий и не использует облегчённый список для форм.

## Выкладка

Миграция базы для этапа не требуется. Живые проверки Telegram и серверная
сверка из этапов 3 и 4 ведутся отдельно.
